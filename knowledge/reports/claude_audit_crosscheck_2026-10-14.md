## Three repaired defect groups

1. **Registry citation was presented as scientific support.** `harvest_registry.py` generated unconditional `SUPPORTED_BY` links from `local_source`; `graph.py` did the same, and `api.find_scientific_basis()` returned a successful basis state for any model or citation. Registry references now remain `CITES`. A current source-fingerprinted `SUPPORTED` or `PARTIALLY_SUPPORTED` assessment is required for model support edges, with state, notes and scope retained. Legacy registry-only support links are also downgraded to citations. The basis API distinguishes partial, unchecked, absent and stale support, preserves citation paths, and reports aggregate `basis_state`; top-level `state=OK` retains its historical meaning of successful API lookup. Source support does not verify the implementation or its physical validity.

2. **Extraction and test metadata could imply evidence beyond their actual scope.** The initial snapshot contained eighteen equation forms explicitly saying `NOT RENDERED` or `OCR-garbled`; thirteen retained model links in their source records. Their graph nodes and `FOUND_IN` evidence remained visible, while `IMPLEMENTS`/`IMPLEMENTED_IN` edges were withheld for incomplete bodies. Subsequent source-page recovery superseded all eighteen damaged forms without removing their history. Equation lookup and task context continue to expose `transcription_state=INCOMPLETE_TRANSCRIPTION` and warnings when applicable. Historical notes about earlier conversion damage do not flag a current equation recovered from the original PDF, such as `EQ_NTRS_19710019929_B679AC9F`.

   Separately, the old test harvester gave every function in a file that file's benchmark classification and PDF citation. An unrelated requirements bookkeeping test could therefore appear as a SP-125 benchmark. Function records now use their exact class-qualified AST function body/name and local citations. Unlocated functions become conservative unit tests; unrelated module citations and tolerance words are not inherited. Module benchmark candidates have explicitly module scope. Local benchmark classification remains a heuristic and is never experimental validation.

3. **Keyword promotion labels were conflated with execution reach and validation.** This directly confirms PDF pp. 12 and 36: Bartz and Sieder–Tate were labeled screening despite use in MDO cooling, while opt-in spray entries could be labeled optimizer coupled. `execution_reach.py` now provides bounded AST import/direct-call evidence for explicitly mapped symbols, with file/line locators and SHA-256 fingerprints. The inspected optimization callable reaches `solve_engine → solve_cooling → cooling_march → bartz_hg/sieder_tate_hc`. Spray drag and evaporation have explicit parcel-analysis API routes; the bounded scan finds no optimizer path for them. Unmapped models and unresolved object/dynamic dispatch remain `UNKNOWN`; absence of a static path is not proof of unreachability.

   Legacy `promotion_status` and `basis_class` values remain inspectable with explicit heuristic-basis fields. They are not execution or scientific authority. Registry records now separately expose `software_verification_state` and `physical_validation_state`: verification claims are reported rather than treated as newly executed; physical validation is reported or unknown, never inferred from tests. Static reach explicitly records `runtime_trace_state=NOT_RUN` and `optimizer_leverage_state=NOT_MEASURED`. No traced MDO run or Jacobian leverage measurement was performed by this subtask.
