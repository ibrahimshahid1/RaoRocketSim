\chapter{Engine MDO, Requirements, Re-evaluation and Run Records (S13--S14)}\label{ch:s13-s14}

\lead{Scope of this chapter}
Stages \stagetag{S13} and \stagetag{S14} close the data flow. \stagetag{S13} is a parallel branch that replaces the sequential stages S03--S12 with one coupled, differentiable whole-engine evaluation, the multidisciplinary-design-optimization (MDO) layer in \code{raosim/mdo/}, and with a requirement layer (\code{raosim/requirements.py}). \stagetag{S14} turns any result, sequential or MDO, into traceable outputs: the authoritative host re-evaluation through \code{raosim.design.design_nozzle_v2}, versioned snapshots and their comparison, the four-valued job verdict, the hashed run record, the expected-part manifest, the model-provenance audit and the physical-release evidence gate (Figure~\ref{fig:s13-s14-flow}).

Everything below was checked against the working tree on 5 November 2026 (commit \code{d636d85} plus uncommitted edits). Where documents or header comments disagree with the code, the code is reported and the disagreement is listed in Sections~\ref{sec:s13-limits} and~\ref{sec:s14-limits}. No result in either stage is hardware evidence: every report carries \code{hardware_qualified=False}, and the solver vocabulary is \emph{screening} and \emph{preliminary}.

\subsection{What the header comments establish}\label{sec:s13-comments}

\lead{Package rules (mdo/\_\_init\_\_.py, plan section 0.1)}
\emph{Pure-numerical}: no CAD, file I/O or host callbacks in the differentiated path; discrete choices enumerated outside the traced core; converged states differentiated by the implicit function theorem (IFT), never by unrolling; smooth conservative envelopes instead of \code{max()} where the nonlinear program (NLP) needs derivatives; authoritative re-evaluation host-side.

\lead{Problem definition: schema, scaling, bounds, material\_map}
\begin{itemize}
\item \textbf{schema.} Fixed requirements and architecture constants are separated from the continuous design vector; channel count, bus voltage and pintle architecture are not variables. Electric constants come from one registered technology set shared with \code{raosim.pumps} (default \code{repository_screening_v1}; alternative \code{lee2021_ijass_electric_pump}); \code{pump_specific_mass} remains an MDO-only screening value. \code{for_thrust} scales channel count, pintle diameter (blockage factor mid-band) and pump speed (specific speed) with thrust. O/F is offered only with sampled surfaces, because with constant $\gamma$, $T_c$, $R$ it ``would change the propellant mass split without changing combustion''.
\item \textbf{scaling.} $z=(x-\mathrm{lo})/(\mathrm{hi}-\mathrm{lo})$ conditions O($10^6$) pressures with O($0.1$) fractions (Martins and Ning 2021, ch.~4).
\item \textbf{bounds.} Replaces the hard-coded $P_c\in[1.5,6]$\,MPa, $\varepsilon\in[3,40]$ box. Pc windows are search guidance with \code{hard_validity=False}: pressure-fed 0.3--1.8\,MPa (SP-125 ch.~V), electric pump 1.5--6\,MPa (\emph{repository finding}, \code{literature=False}), gas generator 3--15, expander 2--10, staged combustion 5--25\,MPa (Parsley and Zhang 2004). Only \code{electric_pump} is implemented. $\varepsilon$ is bounded by the same chart grid that \code{chart_domain_margin} screens.
\item \textbf{material\_map.} Liner and closeout are mapped separately (SP-8087 sec.~2.1.3.1) and atomically or not at all; the comment records that \code{--material GRCop-84} once optimized a NARloy-Z-class liner (12\,\% conductivity, 21\,\% modulus and 200\,K allowable-temperature error).
\end{itemize}

\lead{Thermochemistry and propellants: properties, propellants, coolant\_htd}
\begin{itemize}
\item \textbf{properties.} CEA is never differentiated: states are sampled offline (\code{scripts/sample_cea_surface.py}) and interpolated with Fritsch--Carlson (1980) slopes and zero-twist bicubic Hermite patches (C$^1$). Queries are clamped only to stay finite; \code{domain_violation} becomes a constraint. The surfaces are ``a differentiable stand-in, not the truth source''. Hash-pinned tables are packaged for LOX/RP-1, LOX/LCH4, LOX/LH2 and N2O4/MMH (\code{raosim/data/cea_tables/catalog_v1.json}).
\item \textbf{propellants.} Gases from Sutton Table 5-5 via \code{raosim.propellants}; $L^*$ from SP-125 Table 4-1; wall limits from SP-8087 (RP-1 728\,K; furfuryl alcohol, Aerozine-50 589\,K). Hydrogen has no coking limit (\code{None}); methane values are flagged \code{estimated=True}.
\item \textbf{coolant\_htd.} Nasuti and Pizzarelli (2021) Eq.~(9), $\frac{q_w}{G f_w}(\beta/c_p)_b>K$, $K=0.187$, Darcy $f_w$, bulk properties. Not live: the march carries four constant coolant properties and no $\beta$, and a constant-property evaluation ``misses precisely the peak''. Methane and hydrogen are therefore reported unavailable until a CoolProp-sampled $(T,p)$ surface exists (Bell et al.\ 2014; Huber et al.\ 2009 for RP-1). The criterion errs toward predicting deterioration; buoyancy is neglected.
\end{itemize}

\lead{Discipline blocks: grid, cooling, injector, pintle, pump, mass, structures, envelope}
\begin{itemize}
\item \textbf{grid.} Fixed-topology analytic contour, default $4+6+13+1=24$ stations. The chamber uses the four-section construction of \code{raosim.chamber_geometry} with the barrel solved so injector-face-to-throat volume equals $L^*A_t$ (SP-125 printed p.~88); the former $L^*/CR$ barrel over-stated the 13\,kN chamber by 20.1\,mm and wetted area by 11.7\,\%. The divergent wall is the Rao/TOP quadratic B\'ezier, not the exact Rao contour.
\item \textbf{cooling.} Bartz (1957) $h_g$ with the $\sigma$ factor; recovery factor $\mathrm{Pr}^{1/3}$; fin efficiency $\tanh(mH)/(mH)$; Sieder--Tate $0.027\,\mathrm{Re}^{0.8}\mathrm{Pr}^{1/3}$ with $\mu_w=\mu_b$; Darcy losses with $64/\mathrm{Re}$ and Blasius/Swamee--Jain; counterflow first-order upwind march. Residual $R_i=T_{wg,i}-[T_{aw,i}-q''_i/h_{g,i}]$ solved by Newton, differentiated by the IFT. \code{land_min} is reported, not clipped; the coking margin uses $T_{wc}=T_{wg}-q''t_w/k_w$ against 728\,K (SP-8087; Sellers 1961). NumPy twin parity about $10^{-9}$; quasi-2-D comparison deferred (Phase 4b).
\item \textbf{injector.} Incompressible orifice $G=C_d\sqrt{2\rho\Delta p}$, total momentum ratio (TMR), spray angle $\mathrm{atan2}(m_r\cos\delta,m_a+m_r\sin\delta)$ (Escher $\mathrm{TMR}^{1/2}$ and Son 2015 named as deferred upgrades), blockage factor $\mathrm{BF}=Nw/(\pi D_p)$, Son (2017) two-branch minimum area as a consistency inequality, and $\min(\chi_f,\chi_o)\ge0.2$ from SP-125's 15--20\,\% rule, ``not a universal chug boundary''.
\item \textbf{pintle.} \code{fixed_slotted} (the five-part coaxial CAD and cold-flow article) or \code{son_movable} (numerical only; host CAD refused). Post mass over a 3$D$ body length minus slots (oracle \code{mass_ledger.injector_mass_ledger}); hoop screen $p\,r_o/t$, which bounds the Lam\'e bore stress, against closeout yield over its SP-8087 factor; wall fit $t\le0.8\,D/2$; Son opening $\ge0.1$\,mm at minimum throttle; centre-gap and module fits.
\item \textbf{pump.} $N_s=\omega\sqrt Q/(g_0H)^{3/4}$, $N_{ss}$ from NPSH; a C$^1$ log-Gaussian $\eta(N_s)$ replacing the C$^0$ binned estimator, calibrated to SP-125's 60--85\,\% band but ``not a fit to SP-125 Fig.~6-23''; $P_e=P_{hyd}/(\eta_p\eta_m\eta_{inv})$; tip-speed (SP-8109) and suction (SP-8052) margins; Lee (2021) battery epigraph with energy- and power-limited masses kept separate.
\item \textbf{mass.} Pappus shell volumes for liner, lands (area fraction of the channel annulus) and closeout; SP-125 eq.~8-32, a tank formula, only corroborates the geometry. The docstring says the closeout follows a fixed ratio; the code default \code{closeout_sizing="hoop"} sizes $t_j=\mathrm{FoS}\,p_c r_o/\sigma_y$ per station (SP-125 printed p.~109).
\item \textbf{structures.} Covers SP-8087 sec.~2.1.3's three jobs: hoop support (in \code{mass}), nozzle collapse under overexpansion (SP-8007 sec.~4.2.3 via NTRS 19690013955) and throat support (reported with a caveat). The rib-supported liner buckling screen is explicitly not SP-125 eq.~4-29; collapse is distinct from separation.
\item \textbf{envelope.} SP-125 sec.~2.1 item 6 cylinder, computed to the jacket outer radius and from injector face to exit only: a \emph{lower bound}, since the bolted flange (285.5\,mm around a 177\,mm chamber at 13\,kN) is the largest diameter.
\end{itemize}

\lead{Coupling and output contract: assembly, engine, nozzle, state}
\code{assembly} keeps the original skeleton residuals only as ``integration scaffolding''. In \code{engine} the outer state $(R_t,\dot m)$ feeds the grid, cooling is an inner IFT solve, and the pump rise closes the hydraulic edge, $\Delta p_{rise}=P_c(1+\chi)+\Delta p_{regen}+\Delta p_{line}-P_{tank}$ (\code{engine.py:370-373}), with \code{line_dp_allowance}=0. The only genuine two-way loop (spray $\rightarrow\eta_{c^*}\rightarrow\dot m$) is off by default and measured by \code{ablation_delta}. \code{nozzle} forbids inferring geometry availability from finite coordinates. \code{state} emits fixed-shape pytrees in which an unsupported quantity is \code{NaN} with a false availability flag, never a physical zero.

The manifest is ``software policy around equations implemented in the discipline modules; it does not invent new physical limits''. Each row declares a \code{basis_class}, and a \code{literature} row must have a \code{source_id}. The code holds 36 rows (28 hard, 7 final gates, 1 report-only; 15 literature, 6 numerical contract, 5 repository rule, 4 requirement, 4 geometric definition, 2 model-validity domain), listed in Table~\ref{tab:s13-manifest}.

\code{constraint_metadata} (\code{:387}) is host policy: coking applies to coking coolants and HTD to supercritical ones; an uncatalogued propellant makes both applicable and unavailable (\code{COOLANT_UNRESOLVED}). \code{status_from_rows} (\code{:542}) returns \emph{fail} for a known finite negative margin, else \emph{unknown} if any required row is unavailable, else \emph{pass}. \code{objectives} defines \code{min_electric_package_mass} and the default \code{min_dry_mass_partial} (electric branch plus liner, lands, closeout and pintle post): ``electric feed hardware is not an engine dry mass''.

\lead{Optimizer and evidence: nlp, convergence}
\code{solve_min_mass} minimizes the selected mass subject to $I_{sp}\ge I_{sp,min}$ and every enforced margin $\ge0$; thrust is closed inside each evaluation. The constraint Jacobian uses \code{jax.jacrev} because forward mode through the nested Optimistix solves ``drops the tangent of the geometry-only min-aggregated margins''. Coking is enforced through the film-fraction lever, so the frontier is thermally limited. \code{_GuardedProblem} turns a failed trial point into a finite penalty (central-difference fallback for failed derivatives); \code{kkt_check} recomputes stationarity with non-negative least-squares multipliers (pass at $\le10^{-4}$, feasibility $\le10^{-5}$; repository thresholds) and gates \code{success}; Sobol multi-start counts basins; \code{pareto_frontier} warm-starts only from gate-passing floors. \code{convergence} implements the plan's $<0.5$\,\% station-doubling criterion at a fixed design and re-optimized; its docstring reports a coking-margin shift of about 5\,\% of scale for the fixed 13\,kN design against about 0.26\,\% in the re-optimized objective, and states the studies ``are evidence, not gates''.

\subsection{Maturity, limitations and known defects}\label{sec:s13-limits}
\begin{itemize}
\item \textbf{Maturity.} Plan phases 0, 1, 8 done; 2 partial (coolant surfaces unwired); 3, 4a, 5--7, 9, 11 WIP; 4b (quasi-2-D regen) and 10 (multipoint) not started. All physics is screening; pump-efficiency shape, $\eta_{c^*}(\mathrm{TMR})$ and film effectiveness are surrogates (\code{MDO_GUIDE.md} sec.~9).
\item \textbf{Scope.} One operating point; electric pump only; TOP/B\'ezier bulk contour; thrust blind to the contour ($C_F=\eta_{CF}C_{F,ideal}$); no line losses, film-injector hardware or fatigue life; methane and hydrogen stop at the coverage preflight unless \code{--allow-incomplete-physics} (physics then \emph{unknown}); partial-mass objective; \code{son_movable} has no host handoff; the audited 13\,kN optimum sat on bounds and edges.
\item \textbf{Chart-domain drift.} With $\varepsilon\ge5$, the \code{constraints.py} docstring ($\varepsilon\in[4,50]$), the failing tests and the documented 13\,kN optimum at $\varepsilon=4.0$ (26.227\,kg; \code{MDO_GUIDE.md} sec.~4b) are stale; that optimum is now out of bounds and has not been re-established.
\item \textbf{Header comments behind the code.} \code{mdo/__init__.py} and plan Phase 9 describe a 10-variable vector; the \code{schema.py} docstring lists four variables and \code{of_design_space} says ``10-dimensional''; the code has twelve plus optional O/F. \code{mass.py} describes ratio-based closeout; hoop sizing is the default.
\item \textbf{Two material mappers.} \code{resolve_requirement} writes liner fields itself (\code{requirements.py:567-585}) rather than through \code{with_materials} as the CLI (\code{run_nozzle.py:2068-2073}) and jobs (\code{job.py:1071}) do; it records no material name and no closeout.
\end{itemize}

\subsection{Developer notes}\label{sec:s13-dev}
A new limit or screen is a margin in its discipline block, a key in \code{EngineResult.constraints} and one \code{ConstraintSpec} with \code{basis_class} and \code{source_id}; NLP rows, \code{EngineState}, snapshots and metrics derive from it, and it needs parity and AD/FD tests. A new design variable touches \code{_DESIGN_BASE_FIELDS}, \code{DesignVector}, \code{scaled_design_space}, \code{job.VARIABLE_DIMENSIONS} and the resolved-input contract, followed by the dead-variable check of \code{MDO_GUIDE.md} sec.~8. A propellant needs a \code{PropellantSpec} with its wall-side mechanism and a sampled table in \code{catalog_v1.json} (or \code{register_propellant}). A feed architecture needs \code{requirements._SUPPORTED_FEED}, a \code{JOB_CAPABILITIES} row and a discipline block together; an objective needs a \code{MassObjective} and an \code{execute._OBJECTIVE_IMPLEMENTATIONS} entry (a mismatch raises at import). A contour model implements \code{ContourProvider} and reports failure through \code{ContourOutcome}; a requirement needs an explicit \code{RequirementCoverage} row.

\subsection{What the header comments establish}\label{sec:s14-comments}

\lead{design.py}
A one-line header (``High-level design-gated nozzle workflow''). For the current CLI, \code{design_nozzle_v2} is the authoritative re-evaluation; the sequential runner imports only its spec dataclasses and \code{throat_radius_for_target_thrust}. \code{hardware_qualified} is fixed to \code{False} (\code{design.py:427}); the MDO bridge requests \code{preliminary} mode.

\lead{postprocess.py and resolved\_inputs.py}
The bridge is ``intentionally outside the differentiated path'' and keeps three rules: shared inputs are mapped, not defaulted; unavailable physics (film-injector hardware, complete engine mass) stays unavailable; the authoritative result and artifacts stay attached. The code adds two facts the header omits. When a versioned \code{EngineState} exists (optimizer, Pareto and job paths), the solved $\gamma$, $T_c$, $R$ and ideal c-star are pinned into \code{design_nozzle_v2} as a \code{PinnedChamberState} and $\eta_{c^*}$ is frozen from the MDO state, so the authoritative pass does not recompute thermochemistry; the \code{--engine-mdo} path passes a legacy \code{EngineResult} without that state, and there the host resolves its own (\code{_pinned_chamber_state_from_mdo}, \code{postprocess.py:762}). And \code{to_design_input} refuses \code{son_movable} (\code{:203-214}). \code{ResolvedEngineInputs} (``remediation item 9'') resolves every shared convention once, in SI, with an explicit \code{None} and reason for a missing value; \code{crosscheck_design_input} turns handoff drift into a named warning and \code{input_integrity=fail}.

\lead{snapshot.py}
``Missing physics is data, not zero'': unavailable values are \code{SnapshotValue(value=None, availability_reason=...)}, and MDO chamber and injector mass placeholders are never exported as zero mass. \code{compare_snapshots} compares common scalars and normalized profiles across eight sections with \code{abs_tol}$=10^{-9}$, \code{rel_tol}$=10^{-6}$ by default and exact equality for categorical fields.

\lead{contour\_validation.py}
Not a second inner-loop provider: after optimization it may solve the independent Rao variational/MOC problem at the solved state and fails closed. A convergence-domain artifact must cover the exact context, the solve must pass numerical and MOC closure gates, an independently refined BDE solve must agree at common coordinates, Rao (1999) Eq.~(5) must be valid, performance must come from the direct C--D--E surface integral and every discrepancy must be finite. Missing evidence is \emph{unknown}, an invalid region or exceeded tolerance is \emph{fail}, and the TOP wall is never substituted. The four tolerances are ``project screening policy, not literature qualification limits''; the validator runs only when a job names it.

\lead{execute.py and run\_record.py}
The flow is ``resolve job $\rightarrow$ solve $\rightarrow$ EngineState v2 $\rightarrow$ resolved inputs $\rightarrow$ authoritative traditional parity pass $\rightarrow$ snapshot $\rightarrow$ targets $\rightarrow$ verdict''. The verdict is four-valued because non-convergence is not evidence of impossibility and an unavailable model is not evidence of soundness (list below). Gates evaluated only by the MDO and gates owned by the traditional pass are merged per key: \emph{fail} dominates, absence gives \emph{unknown}. \code{RunRecord} separates report completeness from feasibility (``a complete report can describe a failed solve''), writes each JSON through a temporary file and atomic replace, records its SHA-256 in \code{manifest.json}, and sets \code{hardware_release: false}.

\code{_verdict} (\code{execute.py:248-272}) reduces the statuses in this order:
\begin{enumerate}[itemsep=0pt]
\item SOLVER\_FAILED (exit 4) if \code{workflow}, \code{numerical}, \code{input_integrity} or \code{report_publication} is \emph{fail};
\item CANDIDATE\_VIOLATES (1) if any other status is \emph{fail} or a target fails;
\item INDETERMINATE (3) if a required key is missing (\code{workflow}, \code{optimizer}, \code{numerical}, \code{physics}, \code{requirements}, \code{workflow_readiness}, \code{input_integrity}, \code{requirement_coverage}, \code{model_consistency}), a status is neither \emph{pass} nor \emph{not\_applicable}, or a target is unknown;
\item MET (0) otherwise.
\end{enumerate}

\lead{build.py}
Two competing build paths once let the repository report a ``complete'' ledger for an engine missing whole subsystems; this module enumerates the parts, each built and measured or unavailable with a reason, ``never absent and never zero''. The code lists 27 parts, from liner and closeout through pumps, battery, valves, gimbal and harness. Fidelity runs \code{L0_NUMERICAL_ONLY} to \code{L5_QUALIFIED_HARDWARE}; it is achieved, not requested, set by the least complete part, and L5 ``is never awarded automatically''. A path-and-hash artifact is recorded as unverified at L0.

\lead{model\_registry.py and release\_readiness.py}
The registry ``deliberately distinguishes a published equation from a repository heuristic''; a citation does not validate a particular use. \code{audit_model_registry} fails on a missing declared local source, a published entry without one, empty metadata, or a repository-sourced entry not labelled heuristic, policy or schedule. The release module keeps numerical checks and CAD topology apart from physical release: 17 requirements (ten engine, two injector, two regenerative wall, three pump), each needing a record with result, configuration identifier, artifact SHA-256, reviewer and date. The default report is blocked, and the module ``never sets \code{hardware_qualified}''.

\subsection{Maturity, limitations and known defects}\label{sec:s14-limits}
\begin{itemize}
\item \textbf{The authoritative pass is another screening model:} preliminary mode, constant-property or pinned thermochemistry; held-out CEA/CoolProp, quasi-2-D thermal checks and correction iterations remain TODO (Phase 11).
\item \textbf{MET is effectively unreachable for jobs.} \code{_model_consistency} returns \emph{unknown} whenever any compared field differs or is not comparable, and the comparison applies $10^{-9}$/$10^{-6}$ numerical tolerances to two different screening models. The 2026-09-09 smoke run recorded 17 differences and 79 missing comparisons; \code{MDO_REMEDIATION_AND_OUTPUT_CONTRACT.md} reports about 42\,\% peak wall temperature, 6.5\,\% jacket pressure drop and 22\,\% radius-profile differences at its representative point. Until field-specific tolerances exist (its sec.~11, item 1), a job is at best INDETERMINATE.
\item \textbf{Release evidence ignored on MDO paths.} The MDO dispatch (\code{run_nozzle.py:3830-3835}) precedes the \code{--require-release-evidence} checks (\code{:3938-3945}) and evidence loading (\code{:4044}), and \code{to_design_input} carries neither \code{release_evidence_manifest} nor \code{configuration_id}; the flags are silently ignored on all three MDO branches and the embedded report always shows the default blocked state.
\item \textbf{Registry coverage.} None of the 61 entries covers an MDO surrogate (pump efficiency, film effectiveness, battery epigraph, HTD, closeout sizing); their provenance is only in the manifest and comments.
\item \textbf{Part package always partial.} \code{execute._PART_ARTIFACT_KEYS} is empty, so the uniform-wall \code{thrust_chamber_wall.step} is an unattributed artifact; no part reaches L1 or above.
\item \textbf{Capability and enumeration drift.} \code{JOB_CAPABILITIES} names \code{raosim.mdo.feed} as the \code{electric_pump} implementer; no such module exists. \code{job.ENUMERABLE_SELECTIONS} lists \code{channel_count}, but nothing reads it; \code{expand_architectures} enumerates only propellant, liner and closeout materials plus any variable requested in \code{enumerate} mode, so there is no channel-count axis.
\item \textbf{Documentation drift.} \code{MDO_REMEDIATION_AND_OUTPUT_CONTRACT.md} states EngineState schema 2, inputs 1.1.0 and 59 metrics (code: 3, 1.2.0, 64); the taxonomy's ``its own thermochemistry'' holds only for \code{--engine-mdo}.
\end{itemize}

\subsection{Developer notes}\label{sec:s14-dev}
A new MDO-to-host mapping goes first into \code{resolve_engine_inputs} (it owns conventions), then into \code{to_design_input}, with \code{crosscheck_design_input} naming any drift. A new compared quantity needs \code{SNAPSHOT_FIELD_MANIFEST}, both snapshot adapters and, if targetable, a metric. A new status goes into \code{_execute_resolved_engine_job} and, if mandatory, \code{_REQUIRED_STATUS_KEYS}, keeping the order of \code{_verdict}. Report kinds need a \code{JobCapability} row and a \code{RunRecord.finish} payload; parts a \code{PartSpec}, and attribution a \code{_PART_ARTIFACT_KEYS} entry plus a producer validation record; models a \code{ModelProvenance} entry; evidence items a \code{ReleaseRequirement}.
