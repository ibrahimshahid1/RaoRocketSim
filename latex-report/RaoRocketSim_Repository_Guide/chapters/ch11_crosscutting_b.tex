\lead{Scope of this chapter}
The three groups here are not stages of the command-line interface (CLI) pipeline: no file in them is imported by \code{raosim.run_nozzle.main} or by the \code{lrekit} job verbs. Each relates to the pipeline in a different way. \stagetag{X05} (research and offline scripts) \emph{produces} two packaged data products that the multidisciplinary design optimization (MDO) path reads at run time. \stagetag{X06} (knowledge system and source data) \emph{records} the provenance of the pipeline's physics and holds the packaged tables. \stagetag{X07} (test harness) \emph{checks} every stage. Statements come from the files named and, where stated, from commands run on 5 November 2026 with \code{.venv-jax}; the working tree held uncommitted changes to \code{raosim/}, \code{scripts/}, \code{tests/} and \code{knowledge/}, so some observations describe the working tree, not \texttt{HEAD}.

\section{X05: Research and offline scripts}\label{sec:x05}

\subsection{Role in the data flow and call sites}
The data-flow trace finds all 18 \code{scripts/*.py} files standalone: the abstract-syntax-tree (AST) import closure from \code{lrekit.cli} never reaches them. \code{scripts/run_nozzle.py} is the S01 compatibility wrapper, and \code{compare_nasa_reference.py} and \code{nasa_wall_probe.py} belong to X04; X05 is the remaining 15 scripts (2{,}593 lines). They run by hand as \texttt{PYTHONPATH=. python scripts/<name>.py}; the wheel ships only \texttt{raosim*} and \texttt{lrekit*} (\code{pyproject.toml:72-73}), so no script is installed. Three scripts touch CLI data:
(1)~\code{sample_cea_surface.py} wrote the four frozen chamber-property tables in \code{raosim/data/cea_tables/} (commands in \code{docs/audits/CEA_H1_HOST_EVIDENCE_2026-08-22.md}); the MDO loads them through \code{CEA_CATALOG_MANIFEST_RESOURCE} (\code{raosim/mdo/properties.py:64}) and \code{load_cea_catalog_manifest} (\code{:944}) when the chamber-property table is \texttt{catalog}. (3)~\code{tvc_sizing_study.py} runs the other way: it reads the \code{contour.csv} files the CLI writes. \subsection{What the header comments establish}
\lead{J4/J5 convergence diagnostics (ten scripts)}
All share the reference case $\varepsilon=10$, $L_\%=80$, $\gamma=1.4$, $p_a/p_0=0.01$ and the gate \texttt{max\_scaled}~$\le2\times10^{-3}$; their headers are the solver's history. \code{seed_diagnostic.py} states two hypotheses for the historical stall at \texttt{max\_scaled}~$\approx8$ with opposite predictions: under the \emph{seed} hypothesis the stalled point is near-stationary ($\lVert J^Tr\rVert\approx0$) and a 3-point Jacobian does not move the floor; under the \emph{optimizer} hypothesis an accurate Jacobian escapes it (sources: the Phase-6 xfail text, \code{docs/audits/legacy_code_audit.md}, the JHU/APL report). \code{j4_report.py} expects \texttt{rrcs == 58} on the NASA M3.5Perf geometry, \texttt{rrcs}~$\gg1$ on the Rao case (pre-fix: 1), equal BD/DE mass and a JAX solve with \texttt{max\_scaled}~$<0.8$.

\code{theta_b_freeze_sweep.py} predicts closure near $\theta_B=25.5659^\circ$, $k_{df}=0.15216$, exit near $11.1^\circ$. \code{j4_gate_wall_probe.py} states the bell criterion: slope peaks at about $25.57^\circ$ (plus about $0.7^\circ$ discretization overshoot) and falls monotonically to about $11.12^\circ$; the historic $35.6^\circ$ flare at 60\,\% length came from the stale characteristic pairing. \code{theta_b_picard_probe.py} keeps 2026-06-11 values that ``must not be interpreted as evidence against smooth D continuity''. \code{j5_chart_sweep.py} records the J5 de-circularization: pre-J5 ``solved'' angles were a chart echo plus a chord, reproduced by pure geometry to about $0.1^\circ$, so its \texttt{*\_gate} fields are findings, not pass/fail criteria; it quotes Rao's 1960 parabola-fit charts ($\gamma=1.23$) at $30^\circ/15.5^\circ$. \code{plot_reference_topology.py} calls its output ``NOT the Rao optimum''.

\lead{Generators and data producers}
\code{generate_contour.py} fixes \texttt{max\_nfev}~$=4000$, \texttt{wall\_method="bde"}, \texttt{kernel\_d\_fraction\_max}~$=0.7$ (\code{:43-51}) and exits with status 2 if the $2\times10^{-3}$ gate fails, unless \code{--allow-unconverged} (\code{:110-125}); its outputs are ``preliminary design geometry --- NOT hardware-qualified''. \code{generate_regen_nozzle.py} chains \code{bell_nozzle_contour}, Bartz/regen analysis and \code{generate_regen_nozzle} ($\gamma=1.24$, $P_c=7$\,MPa, 80 channels; with \code{--thermal}, a placeholder propellant $M_w=0.022$, $T_c=3500$\,K). \code{sample_cea_surface.py} implements the \S12.2 Phase-2 workflow of \code{docs/subsystems/S13-engine-mdo-and-requirements/DIFFERENTIABLE_ENGINE_MDO_PLAN.md}: \code{--holdout} samples seeded points strictly inside fit-grid cells and compares values \emph{and} gradients with live RocketCEA; \code{--validate-only} applies the same gate to an existing hash-verified table; any breach returns 2 (\code{:197}). \code{rao_existence_scan.py} limits its declared-domain mode to ``fixed-context D-attachment and kernel evidence only'' and refuses to write a domain without both axes, explicit maximum spacings and at least two \code{--resolution-convergence} levels (\code{:278-305}).

\lead{TVC study}
\code{tvc_sizing_study.py} builds a 316L shell from each \code{contour.csv} (thin-wall hoop thickness $t=\text{FOS}\,P_c r/(k_{\text{hot}}S_y)$), a per-axis torque budget (inertia at $\theta_{\max}\omega_c^2$, flex, bearing friction, misalignment, unbalance) and three actuator screens:
\[
N\eta\,\tau_{\text{motor}} \ge \tau_{\text{req}},\qquad
N\omega_{\text{gimbal}} \le \omega_{\max},\qquad
N^2 J_{\text{rotor}} \le k\,J_{\text{load}},
\]
with $k=10$, 30 or 100 for open-loop steppers, closed-loop steppers and servos. Torque and speed bound the gear ratio $N$ from opposite sides; inertia caps it. Cited sources: Oriental Motor/PMD inertia limits; Cowan \& Weir (NTRS 19940025147) for the 4\,Hz bandwidth, $20$--$25^\circ$ phase lag at 1\,Hz and rotor-inertia dominance; Neugebauer et al.\ (ESMATS 2006) for small bearing friction; \code{raosim/materials.py} for 316L ($\rho=8000$\,kg/m$^3$, $S_y=290$\,MPa, matching \code{materials.py:244-247}). Uncited in code: knockdown 0.50, safety factor 2.0, 1\,mm floor (\code{:61-63}), assembly factor 2.2, bearing coefficient 0.003, $0.5^\circ$ misalignment, $4g$ unbalance, flex torque $0.25\,\tau_J$, margin 2.0, gear efficiency 0.85, a priced vendor catalogue and a 3-D-printer bed check.

\subsection{Verification}
Tests exercise two of the 15 scripts. \code{tests/test_cea_surface_validation.py} drives \code{scripts.sample_cea_surface.main} with an injected sampler (no RocketCEA) and pins that the gate checks values and gradients, fails a hash-valid table with wrong values, exits nonzero with a hash-linked report, and never reuses a fit node as a held-out point. \code{tests/test_rao_existence_scan.py::test_existence_scan_cli_runs_without_pythonpath} runs the script as a subprocess without \texttt{PYTHONPATH}; \code{tests/test_rao_convergence_domain.py:609} runs it twice (a hash-valid domain; rejection of unpaired axes). Products are pinned elsewhere: \code{tests/test_cea_catalog.py} pins the hashed table catalog; \code{test_rao_convergence_domain.py:542-568} requires v1 to fail closed and pins v2's identity; \code{tests/test_rao_chart_benchmark.py:244-247} still carries the TODO to pin per-corner delta baselines from a de-circularized \code{j5_chart_sweep.py} host run. All these files passed in the 5 November run except one \code{test_rao_chart_benchmark.py} case (\S\ref{sec:x07}). The other 13 scripts have no test; a static check run for this guide found every \code{raosim} name they import or reference as an attribute still resolves --- evidence against import rot, not against numerical drift.

\subsection{Maturity, limitations and known defects}
\begin{itemize}[nosep]
  \item \emph{Stale records.} The only archived J4/J5 outputs predate the corrections their headers describe. \code{builds/_archive_2026-11-05/j5_chart_sweep.json} (2026-06-11) has no \texttt{de\_circularized} field and an RMS $\theta_N$ error of $1.2\times10^{-15}$\,deg (the chart echo); \code{j4_gate_wall_probe.json} records a $30.57^\circ$ wall peak at 64\,\% length and a $3.62^\circ$ exit, the flare the current header calls historic. No de-circularized J5 record exists, so the benchmark TODO cannot yet be closed.
  \item \emph{Chart change.} With the working-tree chart, \code{lookup_angles(10, 80)} returns $(25.74^\circ, 10.49^\circ)$, not the $30^\circ/15.5^\circ$ quoted by \code{j4_gate_wall_probe.py}, \code{j5_chart_sweep.py} and \code{test_rao_chart_benchmark.py}. The J5 ``systematic delta'' narrative must be re-evaluated against the code.
  \item \emph{Narrow data products.} The B5 domain covers only $\gamma=1.4$, $p_a/p_0=0.01$, $R_t=20$\,mm, $R_d/R_t=0.382$, $R_u/R_t=1.5$; 25 of 65 knots are \texttt{not\_converged}. The CEA tables are frozen-composition surfaces on $P_c\in[1.5,6]$\,MPa with 17 $P_c$ nodes.
  \item \code{generate_contour.py} writes an open surface of revolution (no end caps), not a watertight solid. \code{tvc_sizing_study.py} copies material values, fixes $P_c=3$\,MPa for every case and defaults to \code{/tmp/tvc}; no TVC subsystem exists (\code{docs/program/PLAN_VALVES_LINES_BRACKETS_GIMBAL.md}). Most scripts write into the archived \code{builds/}, recreating it.
\end{itemize}

\subsection{Developer notes}
A new diagnostic goes in \code{scripts/}; take numbers from \code{raosim} instead of restating them and record in the header which repository state they describe. A new CEA table: run \code{sample_cea_surface.py --holdout --holdout-count 0 --report ...} as in the H1 evidence, then update \code{raosim/data/cea_tables/catalog_v1.json} and \code{tests/test_cea_catalog.py} together. A new Rao domain: write a new versioned JSON (never retrofit kernel policies onto an existing artifact; that is why v1 is refused), record command and hash in a host-evidence note, and add a load test. Promoting a script means moving its logic into \code{raosim/} with a model-registry entry and tests; a script result is never a pipeline result.

\subsection{What the header comments establish}
\lead{Authority and provenance}
\code{knowledge/AGENTS.md} ranks sources: the PDF is authoritative; generated Markdown is a derivative, and the graph ``never outranks the PDF it points to''; repository documents and the model registry carry implementation-state authority only (``existing code is not scientific authority merely because it exists''). Every stored object has one provenance kind (\texttt{SOURCE\_STATES}, \texttt{PROJECT\_DERIVES}, \texttt{CODE\_STATES}, \texttt{SYSTEM\_INFERS}, \texttt{IMPLEMENTATION\_CHOICE}, \texttt{EMPIRICALLY\_CALIBRATED}); every model and hard-coded constant carries a \texttt{basis\_class}, and \texttt{UNKNOWN\_BASIS} is never promoted. Registry models keep \texttt{hardware\_qualified: false} (``never asserted''), and ``a numerical parity test is not physical validation''.

\lead{Grounding and retrieval}
\code{ground.py} stores an extraction only if its quote is found as a contiguous, order-preserving anchor within $\pm2$ pages of the stated page (\texttt{GROUNDED} or \texttt{GROUNDED\_PAGE\_SHIFTED}); otherwise it is \texttt{UNGROUNDED}, reported and not stored: ``Token overlap is not proof that a source states a claim.'' \code{index.py} fuses SQLite FTS5 (BM25) with a latent-semantic-analysis (LSA) space --- a truncated SVD of TF-IDF weights, $k=256$, 40{,}000 terms, \texttt{min\_df}~$=3$ (\code{index.py:86}) --- by reciprocal-rank fusion with $K=60$ (\code{:270}). The header's reasons: the system must run offline with only NumPy/SciPy, and the lexical channel keeps symbols such as \texttt{c*} and \texttt{T\_wg} findable. \code{chunker.py} keeps each equation with its introducing sentence and never splits a table; \code{ingest.py} merges identical PDF payloads into one Document with \texttt{alternate\_paths}.

\lead{Review protocol}
\code{packet_queue.py} enforces \texttt{QUEUED} $\rightarrow$ \texttt{DOCLING\_RUNNING} $\rightarrow$ \texttt{RAW\_CAPTURED} $\rightarrow$ \texttt{CANDIDATES\_PREPARED} $\rightarrow$ \texttt{OPUS\_SOURCE\_REVIEW} $\rightarrow$ \texttt{VERIFIED}$\mid$\texttt{REJECTED}$\mid$\texttt{BLOCKED} $\rightarrow$ \texttt{GRAPH\_INTEGRATED} $\rightarrow$ \texttt{TESTED} $\rightarrow$ \texttt{FINAL\_AUDIT\_ELIGIBLE}. Its transition table (\code{packet_queue.py:28-39}) lets only the reviewer role F enter \texttt{VERIFIED}; mechanical roles S1--S3 run Docling, prepare candidates and integrate. \code{work_journal.py} refuses \texttt{ACCEPTED\_SCIENCE}, \texttt{REJECTED\_SCIENCE} and \texttt{FIXED\_VERIFIED} from S1--S3; \code{locks.py} refuses, rather than queues, a second Docling process; \code{session_replay_check.py} requires both unchanged stores and fully resolved steps.

\lead{Limits on each harvest and tool}
\code{harvest_registry.py} resolves PDFs by exact path, never by name similarity. \code{harvest_constraints.py} never relabels a row (\texttt{hard} $\rightarrow$ \texttt{optimizer\_constraint}, \texttt{final\_gate} $\rightarrow$ \texttt{postsolve\_gate}, \texttt{report\_only} $\rightarrow$ \texttt{diagnostic}); unsourced rows become \texttt{SCIENTIFIC\_BASIS\_UNKNOWN} or \texttt{DECLARED\_<BASIS>}. \code{harvest_artifacts.py}: a STEP hash proves current bytes only, and no Measurement, Experiment or Calibration is inferred. \code{standards.py}: holding a PDF is not compliance. \code{quantities.py} stores no values; \texttt{resolve\_symbol("k")} returns several candidates. \code{acquire_sources.py} records byte identity, ``never training eligibility''; \code{verify_collection.py} must ``never certify model validity'', and its \code{catalog/STATUS.md} reports PASS for identity and coverage with zero sources eligible for training.

\subsection{Maturity, limitations and known defects}
\begin{itemize}[nosep]
  \item Every test is software verification; ``a numerical parity test is not physical validation'' (\code{knowledge/AGENTS.md} \S6).
  \item The suite lags the working tree (15 of 24 failures directly from the chart change, two more plausibly), and \code{raosim/rao_top_chart.py} is untracked: committing only tracked changes would break the import of \code{nozzle_geometry}. \code{test_kg_repository_tracking.py} guards tracking for \code{knowledge/} only.
  \item Only the copper argument file is run by a test. It passes BVP flags the B\'ezier path ignores (\code{--max-nfev 0 --n-control 8 --n-kernel 12}), uses the repository-only $R_u/R_t$ extension (\code{--cd-target 0.99 --allow-throat-radius-extension}), runs at the 7\,MPa the sea-level header calls infeasible, and its test does not assert wall feasibility.
  \item \code{docs/agents/TEST_PROMPT.md} calls the sea-level run ``the full benchmark contour (\texttt{--max-nfev 4000})'', but without \code{--contour-method rao-bvp} the flag is inert; its baseline \code{builds/tests/13kn_sl_baseline_summary.json} does not exist, even in the archive. The argument file's claim that spray/$c^*$ coupling is ``blocked with \texttt{--regen}'' no longer holds when the coolant is the cycle fuel (\code{run_nozzle.py:4148-4157}).
  \item \code{test_jax_convergence.py}'s header still describes a ``remaining gap to the 2e-3 gate'' that its assertions contradict, and it runs \texttt{max\_nfev=4000} solves without the \texttt{slow} marker. \code{test_transonic_kernel.py:195-196} cites a pre-reorganization \code{docs/} path.
  \item \code{test_design_workflow.py} batch tests write \code{builds/vNNN} folders (the data-flow trace attributes most of the 454 archived ones to tests driving \code{main.py}). \code{publish.yml} can publish a tag on which the Test workflow has not passed.
\end{itemize}

\subsection{Developer notes}
Module tests go in \code{tests/test_<module>.py}: write only to \texttt{tmp\_path}, guard optional dependencies with \texttt{pytest.importorskip}, mark minute-scale solves \texttt{slow}, and cite corpus PDF and page for literature anchors (\code{harvest_repo.py} classifies a test above \texttt{unit\_test} only on that evidence). A JAX port needs a NumPy-oracle parity test plus an AD-versus-FD \code{*_gate.py}. A CLI regression case is an \code{examples/cli/*.args} file with a provenance header plus a subprocess test with \code{--out} under \texttt{tmp\_path}. CI lives in \code{.github/workflows/test.yml}; a \texttt{testpaths} entry in \code{pytest.ini} would make root collection explicit.
