The fourteen pipeline stages S01--S14 in the preceding chapters follow one run of \code{raosim.run_nozzle.main} from argument parsing to \code{summary.json}. Five groups of code sit beside that pipeline rather than inside it, so for each the first question is \emph{how it relates to the pipeline at all}. The answers come from the static import closure in the data-flow trace (161 in-scope modules: 125 reachable from \code{lrekit.cli}, 7 only through the legacy entry, 11 from no CLI) and from the call sites (Figure~\ref{fig:x-relations}). X01 is a \emph{parallel solver backend} and leaf library, reached only by \code{--contour-method}~\code{rao-bvp} and the S13 MDO branches; X02 is a \emph{handoff contract} plus one export verb; X03 is the \emph{legacy} front end with its own console script, units and output tree; X04 is an \emph{oracle} that the rao-bvp path hashes but never executes; X08 is \emph{orphaned} library code. None of the five executes physics on a default \code{lrekit} run.

\section{X01 Differentiable JAX core}\label{sec:x01-jax}

\subsection{Role in the data flow, call site, inputs and outputs}

\code{raosim/jax} is, in its package docstring's words, ``a \emph{separate solver backend} living inside the same repo'' that re-expresses the throat-to-contour numerics of \code{raosim.rao_variational} in JAX so that the Rao boundary-value-problem (BVP) residual is differentiable end to end. It has two independent consumers.

\textbf{The S06 Rao BVP (opt-in).} \code{rao_variational.solve_rao_bvp} (\code{:5901}) keeps seeding, the NumPy kernel, reliability gating and output assembly, and delegates only the inner least-squares step. At \code{:6021-6071} it branches on \code{config.solver_backend} (default \code{"jax"}, \code{:641}): with \code{solve_theta_b=True} it calls \code{theta_b_solve.least_squares_jax_theta_b} (\code{:6029}), otherwise \code{api.least_squares_jax} (\code{:6069-6071}); \code{"numpy"} selects SciPy \code{least_squares} with finite-difference Jacobians. From the CLI this runs only when \code{run_nozzle._solve} (\code{run_nozzle.py:1464}) receives \code{--contour-method}~\code{rao-bvp}; \code{--backend} defaults to \code{jax} (\code{:2953}). The same \code{"jax"} default is set in the v2 design spec (\code{design.py:170}) and in the MDO post-solve check \code{mdo.contour_validation} (\code{:183}).

\textbf{The S13 engine MDO.} \code{mdo.grid}, \code{cooling}, \code{engine} and \code{assembly} import the closed-form leaves \code{jax.primitives} (\code{mach_from_area_ratio}, \code{isentropic_pressure_ratio}) and \code{jax.thermal} (\code{bartz_hg}, \code{recovery_temperature}, \code{sieder_tate_hc}, \code{schmucker_separation_margin}, \code{ambient_thrust_coefficient}). The MDO does not call the BVP: \code{run_nozzle._mdo_contour_request_error} (\code{:1866}) states that ``the differentiable MDO core remains on its fixed-topology Rao/TOP chart wall''. Ten further \code{mdo} modules and \code{regen_volumes.py:229} import \code{raosim.jax} only for its side effect, the ``repository-wide float64 policy''.

The default contour (\code{--contour-method}~\code{bezier}) never reaches the BVP backend, which is why X01 is cross-cutting rather than a stage. Figure~\ref{fig:x01-flow} shows one inner solve.

\subsection{What the header comments establish}

\lead{Package contract and primitives.} Float64 is mandatory ``for bit-parity with the NumPy primitives''; x64 is switched on at import, so \code{raosim.jax} must be imported before any JAX array is created. The primitives ``mirror, term for term'' the calorically perfect closed forms in \code{raosim.gas_dynamics}, which are cross-checked against \code{propulsion_texts/prmeyer.pdf} and \code{rao1999.pdf}. The J1 gate is $10^{-10}$ parity on closed forms plus round-trip consistency of the two iterative inverses; \code{mach_angle} and \code{prandtl_meyer} guard their \code{sqrt}/\code{asin} arguments so that values and first derivatives stay finite at $M\to1$.

\lead{Residual assembly.} \code{assembly.py} is the JAX form of \code{_unpack_bvp} $\rightarrow$ \code{_rao_bvp_residual_groups} $\rightarrow$ \code{flat()}, exactly what SciPy minimizes; its J2 gate is $10^{-8}$ parity with \code{_scaled_rao_bvp_residual}, ``proving the port changes numerics, not physics''. Its faithfulness notes matter physically: two Mach floors are deliberately not unified ($M=1.001$ for control-surface (CE) nodes and CE mass-flux midpoints, $1.000001$ for kernel-BD, wall-interpolation and left-Mach nodes); CE $x$ is rebuilt from $dx=dr/\tan(\theta+\mu)$ with a $10^{-9}$ fallback step; the kernel BD is a \emph{static} polyline from the NumPy seed, only \code{kernel_d_fraction} is unknown, and the B$\to$D mass flux is a masked partial-segment sum smooth in that fraction. The finite-difference blocks \code{stationarity} and \code{transversality}, and any \code{angle_boundary_mode} other than \code{"free"}, raise at build time; the supported set is the 13-entry \code{SUPPORTED_BLOCKS} (\code{assembly.py:65-69}).

\lead{Inner solve.} ``Two layers, one boundary'': JAX owns only the LM step with the exact autodiff Jacobian. Optimistix LM has no box bounds, so unknowns are mapped by $u=\ell+(h-\ell)\,\sigma(z)$ and every iterate stays inside the box; the header insists that the 0.7 cap on \code{kernel_d_fraction} (``the Option-2 valid-region workaround'') must hold during iteration. Seeds on a bound are nudged by $10^{-3}$, and convergence is judged on the reparametrization-invariant residual. The code adds LM tolerances $10^{-8}$/$10^{-10}$ (\code{api.py:45-46}) and a continuation over \code{jax_constraint_weight_ladder} (default $(1,10,30,100)$, \code{rao_variational.py:676-678}) that up-weights the mass, length and endpoint-pin rows while reporting the unweighted residual.

\lead{Kernel march.} The header records the corrected characteristic pairing (2026-06-11; Anderson, \emph{Modern Compressible Flow} \S11.4; Zucrow and Hoffman Vol.~2 Ch.~17; oracle-proven in \code{tests/test_characteristic_pairing.py}):
\begin{gather*}
\text{along } C^- \ (\text{slope } \theta-\mu):\quad d(\theta+\nu)=+S\,ds,\qquad
\text{along } C^+ \ (\text{slope } \theta+\mu):\quad d(\theta-\nu)=-S\,ds,\\
S=\frac{\sin\theta\,\sin\mu}{r}.
\end{gather*}
The march reaches bit-parity with the NumPy oracle \code{build_kernel} at the BD level because it ports NASA's row policy and $d\theta$-form unit processes; the Anderson-form processes remain tested references but converge ``to a \emph{different} continuum near the axis: axis Mach +9\,\%''. NASA mixes about 5\,\% \emph{raw} rows (the C$^+$ from \code{prev[1]} ends on the throat arc) with about 95\,\% \emph{special} rows (wall point at $\min(\theta_B,\theta_{\text{prev}}+\Delta\theta_{\lim}/2)$); skipping raw rows starves the wall strip ($\nu_w-\theta_w=-0.67^\circ$ at B against the oracle's $+0.68^\circ$). The landed march (after two failed static-shape designs) uses padded shapes $W=n_0+n_{\text{rows}}$ with traced width and pairing offset. Because the pre-clamp wall grid is $\theta_B$-independent, $d(\text{BD})/d\theta_B$ is exact within a row-count window. The start line is a frozen input, and \code{build_start_line} raises \code{NotImplementedError} (``differentiable Kliegel--Levine'', \code{moc_kernel.py:823}), so there are no derivatives with respect to $R_t$ or $\gamma$. Default wall-step limit: $0.5^\circ$ (\code{moc_kernel.py:95}).

\lead{$\theta_B$ as an unknown.} \code{theta_b_solve.py} appends $\theta_B$ to the unknowns and rebuilds BD by \code{march_kernel} on every evaluation, injecting the traced arrays through \code{StaticParams._replace} into the unchanged J2-gated assembly; padding segments have $ds=0$ and are masked. Gate: at the seed angle the live-BD residual equals the static one to about $10^{-8}$. Crossing a grid interval changes the clamp-row index (``a small discontinuity''), so the bounds are $\pm\Delta\theta_{\lim}/4$ around the seed (\code{:166-167}) and are re-centred per ladder rung.

\lead{Gradient API.} J6 v1 gives exact node fields $\partial C_F/\partial M_i$, $\partial\theta_i$, $\partial r_i$ on the solved control surface (a ``manufacturing-tolerance map'' without re-solve), the multiplier tail (about 0 at an optimum), explicit \emph{partial} derivatives at fixed $u^*$ with $\partial C_F/\partial p_a=-(r_E^2-r_D^2)/R_t^2$ pinned as a known-sign gate, and the Jacobian's extreme singular values. $C_F$ follows \code{nasa_moc.surface_thrust_coefficient} normalized by $\pi R_t^2p_0$. Total design derivatives via the implicit function theorem (IFT), bell-wall node maps and the Hessian are deferred to v2; only \code{couple_wall=False} is supported (\code{sensitivities.py:183-187}).

\lead{Thermal leaves.} \code{thermal.py} ports the full Bartz (1957) coefficient with property factor $\sigma$ ($\omega=0.6$),
\[
h_g=\frac{0.026}{D_t^{0.2}}\left(\frac{\mu^{0.2}c_p}{\mathrm{Pr}^{0.6}}\right)\left(\frac{p_c}{c^*}\right)^{0.8}\left(\frac{D_t}{R_c}\right)^{0.1}\left(\frac{A_t}{A}\right)^{0.9}\sigma,
\]
Sieder--Tate $\mathrm{Nu}=0.027\,\mathrm{Re}^{0.8}\mathrm{Pr}^{1/3}(\mu_b/\mu_w)^{0.14}$, recovery factor $\mathrm{Pr}^{1/3}$, the series circuit $q=(T_{aw}-T_c)/(1/h_g+t_w/k_w+1/h_c)$ solved by eight unrolled fixed-point passes at the throat (\code{n_iter=8}), Schmucker $p_{\text{sep}}/p_a=(1.88M_e-1)^{-0.64}$ (\"Ostlund 2002 Eq.~30; corrected 2026-07-22 from a variant ``$\sim1.75\times$ off'' at $M_e=3$), and ambient $C_F$. Constraints sit at closed-form stations (throat, isentropic exit), so no contour march is differentiated; parity with the NumPy twins is the acceptance gate.

\subsection{Verification}

In the full-suite run of 2026-11-05 in \code{.venv-jax} (Python 3.12.14, jax 0.6.2, optimistix 0.0.11; 2832 passed, 24 failed, 1 skipped, 27 deselected), no X01 test file failed. \subsection{Maturity, limitations and known defects}

The rao-bvp path is experimental: README ``Known limitations'' item~5 notes that release-level literature promotion is disabled (\code{BENCHMARK_VALIDATED_AT_RELEASE} is \code{False}, \code{rao_variational.py:862}), and the J4 test pins reliability \code{GEOMETRIC_APPROXIMATION} with the optional MOC wall audit skipped.
\begin{itemize}
\item \textbf{Frozen start line}: no derivative with respect to $R_t$, $\gamma$ or throat curvature through the kernel.
\item \textbf{Capabilities without a production caller}: \code{rao_sensitivities} and \code{plotting.plot_sensitivity_field} (\code{plotting.py:703}) are exercised only by tests; \code{solve_theta_b} has no CLI flag.
\item \textbf{Header drift (code wins)}: \code{__init__.py} calls JAX ``the default for \code{solve_rao_bvp}'', true for the configuration but not for a default CLI run; \code{thermal.py} names \code{jax.design_opt} as its consumer and \code{tests/test_jax_thermal.py} as its gate, but the live consumer is \code{raosim/mdo} and that test file does not exist; \code{assembly.py} cites \code{rao_variational.py:3559} for the SciPy call, which is now at \code{:4682} and \code{:6079}.
\item \textbf{Chart-angle test premise broken}: \code{test_rao_chart_benchmark.py::test_reported_angles_are_solver_outputs_not_chart} fails because the uncommitted SP-125 re-digitization (\code{raosim/rao_top_chart.py}) moved the chart $\theta_n$ at $(\varepsilon,L)=(10,80\,\%)$ from 30.0$^\circ$ to 25.74$^\circ$, within 0.23$^\circ$ of the solver's 25.51$^\circ$.
\item \textbf{Plan direction unmet}: DIRECTION item~1 (``\code{raosim/jax} becomes the only core package'') is not done; NumPy owns the shell and five \code{raosim/jax} files are orphans. (The plan's flip checklist records \code{pin_d_theta=False}; a later STATUS entry records the re-baseline to \code{True}, which matches \code{rao_variational.py:686}.)
\end{itemize}

\section{X02 Spray-parcel mid-tier and OpenFOAM handoff}\label{sec:x02-spray}

\subsection{Role in the data flow, call site, inputs and outputs}

\textbf{OpenFOAM export (a CLI verb).} \code{raosim.cli.main} intercepts the first argument \code{export-openfoam-spray} (\code{raosim/cli.py:11-14}) before the runner; \code{lrekit} reaches it because \code{lrekit.cli.main} forwards every non-job verb. The chain is \code{openfoam.case.cli_main} (\code{case.py:1611}) $\rightarrow$ \code{build_radhakrishnan2018_sheet_vof_case} (\code{:456}) $\rightarrow$ \code{write_openfoam_case} (\code{:1520}). The builder loads its fixture through \code{spray.benchmarks.load_spray_benchmark} (\code{:470}), so this verb is the one CLI path that executes code in \code{raosim/spray}. \subsection{What the header comments establish}

\lead{OpenFOAM export.} \code{case.py} separates two stages of Radhakrishnan et al.\ (2018): Section~2.3 used volume-of-fluid (VOF) with a \emph{water-only} inlet into quiescent air to obtain sheet thickness; Section~2.4 used the 3.03\,g/s annular air as the Eulerian carrier for the Lagrangian droplets. The template is a ``reduced external-gap wedge'' that maps the mechanical opening onto a radial water boundary and ``does not contain the paper's internal center-gap turning passage, so it cannot claim to predict the sheet at formation''; every manifest says so (\code{geometry_fidelity}: \code{reduced_external_gap_not_internal_turning_passage}, \code{case.py:552}). Builders are pure; the target is OpenFOAM Foundation v13, patch \code{20260624}, \code{foamRun} with \code{incompressibleVoF}. The author's sheet thickness and water velocity are targets ``never prescribed'' (\code{:464}); $U_r=\dot m_{360}/(\rho\,2\pi r_{\text{tip}}L_{\text{open}})$, with wedge mass closure to $10^{-12}$ (\code{case.py:503-518}). \code{openfoam/handoff.py} records evidence from a separate VOF extraction; \code{full_sheet_thickness_mean_m} is the \emph{full} thickness, and the handoff is usable only when every gate passes.

\lead{Parcel physics.} The package is ``intentionally opt-in'', and parcel results ``are not eligible for cycle coupling until their conservation and declared literature-validation gates pass''.
\begin{itemize}
\item \emph{Primary sources}: only the movable-pintle \emph{radial sheet} may use the literature-calibrated primary path; annuli, slots and holes become secondary-breakup blobs, and the module ``deliberately does not invent LISA, slot-sheet, or round-jet primary-breakup correlations''. Convention: $\alpha=0$ is radial, $u_x=U\sin\alpha$, $u_r=U\cos\alpha$.
\item \emph{Breakup}: Reitz WAVE/Kelvin--Helmholtz with three coefficient sets that are never blended: \code{reitz_1987} (0.4, 0.865; OpenFOAM ReitzKHRT), \code{radhakrishnan_2018} (0.4, 0.87; their Eq.~5), \code{radhakrishnan_2021} (0.45, 0.87; their Eq.~3). The Rayleigh--Taylor branch copies OpenFOAM's equations and timer but is off by default. Breakup sets the parcel multiplicity so that represented mass is constant and leaves velocity unchanged, so represented mass and parcel momentum are identities.
\item \emph{Drag, dispersion, evaporation}: $C_D=24/\mathrm{Re}\,(1+0.15\,\mathrm{Re}^{0.687})$ for $0<\mathrm{Re}\le1000$, 0.44 above (\code{drag.py:14-33}); eddy life $\tau_e=C_Lk/\varepsilon$, fluctuation $\sqrt{2k/3}$, local generator only; Radhakrishnan, Lee and Koo (2021) Eq.~16, $\dot m=k_cA_d\rho_g\ln(1+B_m)$ applied with negative sign and closed by a caller-named Sherwood model.
\item \emph{Carrier, domain, solver, ledger}: prescribed fields ``without hidden extrapolation''; first-crossing wall/outlet events; ``a mid-tier engineering model rather than a CFD solver'' in which the carrier consumes no sources and droplet temperature and carrier energy are not solved; the ledger closes \emph{parcel} momentum and reports the carrier impulse only as a source demand.
\item \emph{Statistics and fixtures}: $d_{32}=\sum wd^3/\sum wd^2$ by number; Rosin--Rammler by mass, with Radhakrishnan's $\exp(-(d/\bar d)^n)$ named a mass \emph{survival} fraction; Radhakrishnan 2021 Tables~7 and 8 are author CFD, ``never promoted to experimental evidence''.
\end{itemize}

On the Python side, \code{legacy_io} ``intentionally preserve[s] the raw numeric data'' with normalized column names; \code{compare_nasa_reference.py} is ``a visibility tool, not a pass/fail gate'' that reports unavailable metrics explicitly; \code{nasa_wall_probe.py} runs the perfect-nozzle branch (D at the axis end of BD, $\dot m_{BD}$ equal to the kernel mass, DE as the uniform-state characteristic from the C++ \code{FindPointE} closed form) and compares \code{calc_bde_region} with the $i=0$ trace of \code{wall.out}.

\subsection{Maturity, limitations and known defects}

The oracle certifies one configuration, the M3.5 perfect nozzle at $\gamma=1.4$. \code{rao_variational} lists its own blockers: the certificate ``covers only the pinned M3.5 perfect-nozzle case'', ``historical fixture-generator provenance remains unresolved'', and for general contours ``CropNozzleToLength is not ported for exported interior grids''.
\begin{itemize}
\item \textbf{TT$'$ provenance.} No executable is checked in, and searches of the upstream repository and NASA Software Catalog (2026-06-09) found no other generator. Theory-correct Kliegel--Levine gives the axis point $x\approx0.679$, $M\approx1.268$ where the fixture has $x=0.724$, $M=1.5$; the separate \code{nasa_visible_kliegel_levine} path, which keeps the C++ integer-division semantics and its $M\le1.5$ loop, reproduces the fixture within the parity tolerances. The open question is provenance, not numerics.
\item \textbf{Licence notices.} The tree carries \code{license.txt}, but the Python port (\code{raosim/nasa_moc.py}) has no NOSA agreement text, NASA copyright notice or dated modification record, and the repository has no licence file; the 7 October 2026 review lists all three NOSA conditions as open before any public release.
\item \textbf{Stale map.} The topology map predates \code{moc_bounded.py} (2026-09-21), so its ``not yet'' statements need re-checking. Of the 60\,MB tree, only \code{MOC_GridCalc_BDE.cpp} and \code{outputs_M3.5Perf/} are read by code.
\end{itemize}

\section{X08 Library code not reachable from the CLI}\label{sec:x08-unreachable}

\subsection{Role, inputs and outputs}

No CLI path imports these modules: the AST closure from \code{lrekit.cli}, including function-level imports and the legacy \code{main.py} edge, never reaches them. They write no artifacts. Most duplicate or precede something a stage now does. (\code{raosim/__main__.py} is also unimported, but it is the \texttt{python -m raosim} wrapper around \code{raosim.cli.main}; \code{raosim/data/tools/*} belong to X06.)

\subsection{What the header comments establish}

\begin{itemize}
\item \code{flange_cad.py} (354 lines) claims to close a gap: ``the chamber-side flange was not modelled at all -- no ring, no holes''. It builds the ring and an ``orderable'' fastener callout: preload $0.75\times$ proof load for reusable joints (0.90 permanent in code), torque $T=KF_id$ with $K=0.20$ dry and 0.15 lubricated (the code adds 0.18 plated), after Shigley, labelled \code{screening_sized}; ``$K$ \ldots\ scatters by 20--30\,\%''; ``not a qualified joint design'' (no gasket seating stress, flange rotation, preload scatter, thermal gradient or fatigue).
\item \code{thermal_correlations.py} (100 lines, untracked in git): ``source-scoped thermal correlation choices and applicability reports''; bounds are ``Bartz's preliminary-estimation guidance, not a physical validation envelope''. In code: contraction 15--45\textdegree, expansion 7.5--22.5\textdegree, $D_t/R_c$ up to ``about 3''; a curved bell has no single expansion angle, so a missing angle yields \code{UNKNOWN}; it carries Bartz's 40--50\,\% chamber under-prediction warning and refuses to guess a coolant $C_1$ (only RP-1, 0.0214, is built in).
\item \code{trajectory.py} (111): ``simple 1-D point-mass simulation with gravity, drag, and atmospheric density''.
\item \code{jax/bvp.py} (102), \code{pack.py} (62), \code{residuals.py} (261), \code{reference.py} (38): J2/J3 scaffolding (LM wrapper with implicit differentiation, CE layout $[x\,|\,r\,|\,M\,|\,\theta\,|\,\log C]$, vmapped residual leaves at $10^{-10}$ parity, M3.5Perf constants sizing static shapes, \code{MAX_KERNEL_ROWS} $=64$).
\item \code{jax/design_opt.py} (460): maximize $C_F(\varepsilon;p_c,p_a)$ over $(\varepsilon,R_d/R_t)$ subject to a Schmucker margin and a Bartz/Sieder--Tate throat wall limit, with exact gradients (Optimistix BFGS, ramped penalty); ``the differentiable successor to the NumPy feedback loop in \code{raosim.thermal_design}''.
\end{itemize}
